Master Task Cards

Overview​

The Master Task Cards application is a foundational component of Maximo for Aviation that enables the creation and management of master maintenance task definitions.

Master Task Cards serve as templates that define maintenance requirements, frequencies, and procedures for configuration-managed (CM) components and aircraft systems.

Purpose and Function:

Master Task Cards act as the authoritative source for maintenance task definitions that are:

  • Linked to one or more configuration-managed (CM) Part Numbers
  • Used to automatically generate Task Cards for applicable assets (Aircraft or Equipment)
  • Integrated with Operators Maintenance Programs (OMPs)
  • Maintained with full revision control and change tracking
  • Organized by ATA chapters and maintenance phases

Master Task Cards are the bridge between manufacturer maintenance requirements (imported via MTL) and operational maintenance execution (Task Cards on assets). They ensure consistency and compliance across the fleet.

Key Capabilities:

  • Define maintenance tasks with comprehensive frequency criteria
  • Link tasks to configuration-managed part numbers
  • Support multiple frequency types (calendar, meter-based, iterations)
  • Configure task actions that affect related tasks
  • Manage task revisions with full change tracking
  • Generate Task Cards automatically for applicable assets
  • Support check-based maintenance organization
  • Enable task extensions and deferrals
  • Integrate with OMP and BDI for automated Task Card generation

Integration Points:

  • Part Number Master - Links tasks to CM part numbers
  • MTL Application - Source for manufacturer task requirements
  • OMP Application - Organizes tasks into maintenance programs
  • Aicraft and Equipment Application - Displays generated active Task Cards on the Maintenance Plan tab
  • BDI (Build Data Interpreter) - Automates Task Card generation
  • Work Orders - Execution of maintenance tasks
  • Job Cards - Detailed work instructions and resource requirements

The Master Task Card Type field categorizes tasks by their nature and purpose:

Selecting the correct Master Task Card Type is critical as it determines how the task behaves, how Task Cards are generated, and how the task integrates with asset configuration management.

Relationship with Part Numbers​

The relationship between Master Task Cards and Part Numbers is fundamental to Maximo for Aviation's automated maintenance generation and statusing capability.

Part Number Linkage​

Master Task Cards are linked to configuration-managed (CM) part numbers through the Part Numbers tab. This relationship enables:

  • Automatic Task Card Generation - When an asset with a linked part number is validated by BDI, Task Cards are automatically created
  • Component Tracking - Tasks follow components through their lifecycle (installation, removal, shop visit)
  • Configuration Control - Ensures correct tasks are applied based on installed components
  • Maintenance Planning - Links maintenance requirements to specific components

Part Number Table Fields:

FieldDescription
Part NumberCM part number from Part Number Master
DescriptionPart description
VendorPart manufacturer or vendor
DescriptionAdditional description or notes

The Part Number relationship is what enables "configuration-aware" maintenance

  • the system automatically knows what maintenance is required based on what components are installed on each aircraft.

Multiple Part Numbers:

  • A single Master Task Card can be linked to multiple part numbers
  • Useful for tasks that apply to different variants or alternates
  • All linked part numbers will trigger Task Card generation
  • Enables fleet commonality and standardization

Frequency Configuration​

Frequency configuration is one of the most critical aspects of Master Task Cards, defining when maintenance tasks become due. Maximo for Aviation supports multiple frequency definition methods to accommodate various maintenance philosophies.

Frequency Definition Methods​

Master Task Cards support three primary methods for defining when tasks are due:

  1. Intervals and Thresholds - Traditional fixed-interval maintenance
  2. Time-Based Iterations - Sequential calendar-based task progression
  3. Meter-Based Iterations - Sequential usage-based task progression

  • Stop Date - When task is no longer required. The BDI will automatically de-activate the associated Task Cards once the date is exceeded.

Standard Thresholds​

Standard Thresholds define when the first or initial instance of the maintenance task is due. This is distinct from Standard Intervals, which determine the frequency of all subsequent occurrences after the initial task is completed.

Threshold vs. Interval:

ComponentPurposeExample
ThresholdDefines when the FIRST occurrence is dueFirst inspection due at 1,000 FH after installation
IntervalDefines when SUBSEQUENT occurrences are dueRepeat every 5,000 FH after first inspection

Threshold Configuration:

Thresholds use the same structure as intervals but represent the initial due point:

FieldDescription
Frequency TypeCALENDAR or METER
FrequencyInitial threshold value
Frequency UnitsUnit of measure
Apply Adjustment Factor?Apply adjustment calculation

Threshold Examples:

FrequencyUnitsPurpose
1,000.00FHFirst inspection due at 1,000 flight hours
90.00DAYSFirst check due 90 days after installation
500.00FCFirst inspection due at 500 cycles

How Thresholds and Intervals Work Together:

Example: Engine Borescope Inspection

Threshold: 1,000.00 FH (First inspection)
Interval: 5,000.00 FH (Recurring inspections)

Timeline:
0 FH: Engine installed
1,000 FH: First borescope inspection due (THRESHOLD)
6,000 FH: Second borescope inspection due (1,000 + 5,000 INTERVAL)
11,000 FH: Third borescope inspection due (6,000 + 5,000 INTERVAL)
16,000 FH: Fourth borescope inspection due (11,000 + 5,000 INTERVAL)

Thresholds are particularly useful for break-in inspections, initial service checks, or any maintenance that has a different first-time interval compared to recurring intervals.

Multiple Intervals and Thresholds:

A Master Task Card can have multiple intervals and thresholds:

  • Multiple Intervals - Task becomes due when ANY interval is reached (whichever occurs first)
  • Multiple Thresholds - Multiple warning points for different planning horizons
  • Combined - Mix of calendar and meter-based intervals

Example: Combined Frequency

Task: C-Check Inspection
Interval 1: 12,000.00 FH (flight hours)
Interval 2: 72.00 MONTHS (calendar)
Threshold 1: 500.00 FH (warn at 11,500 FH)
Threshold 2: 14.00 DAYS (warn 14 days before calendar due)

Result: Task becomes due at 12,000 FH OR 72 months, whichever occurs first
        Warnings issued at appropriate thresholds for each frequency type

Time-Based Frequency Iterations​

Time-Based Iterations provide a sequential, calendar-based approach to maintenance where tasks progress through a defined sequence of intervals. This method is ideal for progressive inspections, calibrations, or maintenance programs that require different actions at different intervals.

Time-Based Iteration Concept​

Instead of a single repeating interval, Time-Based Iterations define a sequence of calendar-based frequencies. Each iteration can have:

  • Different interval lengths
  • Different job cards
  • Different alert and warning intervals
  • Sequential progression through the iteration cycle

Key Features:

  • Sequential Progression - Task moves from iteration 1 to 2 to 3, etc.
  • Variable Intervals - Each iteration can have a different frequency
  • Iteration-Specific Job Cards - Different work instructions for each iteration
  • Loop Capability - Option to return to first iteration after completing the sequence

Loop Iterations Checkbox​

The Loop Iterations checkbox controls what happens after the final iteration in the sequence is completed:

Loop Iterations = Checked (Enabled):

  • After completing the final iteration, the task returns to Iteration 1
  • The cycle repeats indefinitely
  • Useful for ongoing maintenance programs
  • Example: Calibration program that cycles through inspection depths

Loop Iterations = Unchecked (Disabled):

  • After completing the final iteration, the task stops and the Task Card is made inactive
  • No further work orders are generated
  • Useful for one-time progressive programs
  • Example: Break-in inspection program for new equipment

The Loop Iterations setting is critical for determining whether your maintenance program is cyclical (repeating) or finite (one-time). Choose based on your maintenance philosophy and regulatory requirements.

If the "Iterations of this Frequency" field is left empty for the last iteration in the sequence then the associated task card will continue indefinitely at the last iteration frequency.

Meter-Based Frequency Iterations​

Meter-Based Iterations provide a sequential, usage-based approach to maintenance where tasks progress through a defined sequence of meter intervals. It operates in an almost identical manner to the time based iterations.

This method is ideal for progressive inspections based on operating hours, cycles, or other usage metrics.

Meter-Based Iteration Concept​

Similar to Time-Based Iterations, but driven by meter readings rather than calendar time. Each iteration can have:

  • Different meter interval lengths
  • Different job cards
  • Different alert and warning thresholds
  • Sequential progression through the iteration cycle
  • Variable iterations (different number of occurrences per iteration)

Master Task Card Actions​

Master Task Card Actions provide powerful automation capabilities that allow one task (the "primary" task) to trigger actions on other related tasks (the "secondary" tasks). This feature enables sophisticated maintenance logic and workflow automation.

Actions Concept and Purpose​

What Are Master Task Card Actions?

Master Task Card Actions define automated responses that occur when specific events happen with a primary task. These actions affect secondary tasks on the same asset, enabling:

  • Coordinated Maintenance - Link related tasks so they work together
  • Workflow Automation - Automatically activate, deactivate, or complete related tasks
  • Maintenance Logic - Implement complex maintenance rules and dependencies
  • Event-Driven Maintenance - Trigger tasks based on component installation/removal

Master Task Card Actions are limited to primary and secondary Task Cards for the same CM Item or configuration-managed asset. Actions cannot affect Task Cards on different assets.

Action Types and Triggers​

Master Task Card Actions support multiple action types, each triggered by specific events:

Work Order Completion Actions:

These actions are triggered when a work order generated from the primary Task Card is completed:

Action TypeEffectUse Case
ACTIVATEChanges secondary Task Card status to ACTIVEEnable a task after another task is completed. Example: Activate operational checks after installation task is complete.
COMPLETEMarks secondary Task Card as complete and resets next due dateClaim completion of a related task when primary task is done. Example: Complete follow-up inspection when main inspection is complete.
CREATE WOGenerates a work order from the secondary Task CardAutomatically create work for a related task. Example: Generate calibration work order after equipment installation.
DEACTIVATEChanges secondary Task Card status to INACTIVEDisable a task after another task is completed. Example: Deactivate temporary inspection after permanent fix is complete.

Component Installation Actions:

These actions are triggered when the asset associated with the primary Task Card is installed into a parent assembly:

Action TypeEffectUse Case
ON-ACTIVATEChanges secondary Task Card status to ACTIVE when component is installedEnable tasks when component is installed. Example: Activate operational checks when engine is installed on aircraft.
ON-DEACTIVATEChanges secondary Task Card status to INACTIVE when component is installedDisable tasks when component is installed. Example: Deactivate storeroom maintenance tasks when component goes on-wing.

Component Removal Actions:

These actions are triggered when the asset associated with the primary Task Card is removed from a parent assembly:

Action TypeEffectUse Case
OFF-ACTIVATEChanges secondary Task Card status to ACTIVE when component is removedEnable tasks when component is removed. Example: Activate shop inspection when engine is removed from aircraft.
OFF-DEACTIVATEChanges secondary Task Card status to INACTIVE when component is removedDisable tasks when component is removed. Example: Deactivate on-wing tasks when component is removed.

Reset Job Card Sequence​

The Reset Job Card Sequence checkbox controls whether the job card sequence for the secondary Task Card is reset when the action is triggered:

Reset Job Card Sequence = Checked:

  • Job card sequence is reset to the beginning
  • Useful when you want to restart a job card progression
  • Example: After overhaul, reset calibration job card sequence to start from first calibration

Reset Job Card Sequence = Unchecked:

  • Job card sequence continues from current position
  • Useful when you want to maintain progression
  • Example: Continue with next job card in sequence after completing related task

Activation Delay​

Actions can be configured with a delay before they take effect:

FieldDescription
Activation Delay UnitUnit for delay (DAYS, HOURS, etc.)
Activation Delay PeriodNumeric delay value

Use Cases for Activation Delay:

  • Allow time for post-maintenance stabilization
  • Coordinate with operational schedules
  • Implement mandatory waiting periods
  • Stagger related maintenance activities

Master Task Card Actions provide powerful automation but should be carefully designed and tested. Incorrect action configuration can lead to unexpected Task Card status changes or maintenance gaps.

Status and Revisions​

Maximo for Aviation introduces enhanced status management and revision control for Master Task Cards, providing better change tracking and configuration control.

Status Management​

Status Field:

Master Task Cards have a status field (MASTERPM.PLUSASTATUS) that controls their lifecycle:

StatusDescriptionTask Card Generation
DRAFTMaster Task Card is being developedNo Task Cards generated
ACTIVEMaster Task Card is approved and operationalTask Cards generated automatically
INACTIVEMaster Task Card is no longer in useNo new Task Cards generated. Existing Task Cards are deactivated
PNDREVPending revision (revision in progress)Changes are not put into effect into the new revision is activated
REVISEDPrevious revision (superseded)Historical reference only

Status Workflow:

  1. Create - New Master Task Card created with DRAFT status
  2. Configure - Set up frequencies, part numbers, actions, etc.
  3. Activate - Change status to ACTIVE when ready for use
  4. Revise - Create revision (status becomes PNDREV for new revision)
  5. Supersede - Previous revision changes to REVISED status

Task Cards cannot be created from Master Task Cards unless they are in ACTIVE status. This ensures only approved, validated tasks are used for maintenance generation.

Revision Control​

Revision Benefits:

  • Full change tracking (what changed, when, by whom)
  • Audit trail for regulatory compliance
  • Controlled change management process
  • Prevents accidental modifications to active tasks
  • Maintains historical record of all revisions

Updating Associated Task Cards:

Revising Master Task Cards in OMPs​

Master Task Cards that are part of an Operators Maintenance Program (OMP) have special revision requirements. The revision creation process and activation of the new revision must be performed within the OMP application itself, not directly in the Master Task Cards application.

OMP-Based Revision Process:

When a Master Task Card is included in an OMP:

  1. Navigate to OMP Application - Open the OMP that contains the Master Task Card
  2. Locate Task - Find the Master Task Card in the OMP Tasks list
  3. Initiate Revision - Use the OMP's revision action for the task
  4. Make Changes - Applink to the Master Task Card to make modificiations to it and save. Return to the OMP once changes are made
  5. Activate Revision - Activate the new master task card revision using the change status icon on the OMP Task row within the OMP
  6. Propagate Changes - The system automatically triggers the update to the associated Task Cards by triggering BDI validation for the affected Aircraft.

Be aware that the update of associated Task Cards is not immediate. The time taken for changes to be propagated depends on a numnber of factors including: number of aircraft and how the BDI and asynchronous job crontasks are configured.

When a Master Task Card revision is activated:

  • Automatic Update - BDI updates Task Cards during next asset validation
  • Manual Update - Use "Update Associated Task Cards?" action for immediate update

Extendable Task Cards​

The Extendable checkbox on a Master Task Card indicates that associated Task Cards can have their due dates or due counts extended through a controlled process.

Extendable Checkbox:

  • When checked, Task Cards generated from this Master Task Card can be extended
  • Extensions are created through Task Card Extension records
  • Extensions can be subject to approval workflow
  • Provides controlled flexibility for operational needs

Task Card Extension Process:

  1. Identify Need - Task Card approaching due date but cannot be completed
  2. Create Extension - Create Task Card Extension record
  3. Justify Extension - Document reason and new due date/count
  4. Approval - Submit for approval (if workflow configured)
  5. Apply Extension - Extension updates Task Card due date/count
  6. Track Extension - Extension history maintained for audit

Use Cases for Extensions:

  • Aircraft grounded for unrelated issues
  • Parts availability delays
  • Operational schedule conflicts
  • Weather or facility constraints
  • Regulatory approval for extension

Task Card extensions must comply with regulatory requirements and manufacturer limitations. Some tasks (especially CMR tasks) may not be extendable or may require regulatory approval.
