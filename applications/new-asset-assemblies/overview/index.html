New Asset Assemblies (CM)

Overview​

The New Asset Assemblies (NAA) application enables a user to create a CM managed asset hierarchy from a Model. The asset hierarchy created can be either:

  1. An entire assembly, starting with an end-item as the top level asset within the assembly. For example, a train set or train car.
  2. A partial asset assembly, where the top level asset corresponds to a position in the Models build Hierarchy at a level of indenture > 1. For example a bogie or wheelset within a train vehicle.

The application enables the user to generate the data, using the Model as a template, from which the Asset records within Maximo will be created from.

Application Usage​

The basic flow of using the New Asset Assemblies application is as follows:

  1. Create a new record. The user can enter a "New Asset" value which will be used as the Asset number of the top level asset. Alternatively the field (PLUSANEWASSET.ASSETNUM) can be configured to use the standard Asset autokey.

  2. Specify a "CM Item" corresponding to the top level asset of the new assembly.

  3. Select a Model/Configuration from the lookup on either field.
    The lookup will present a list of all values applicable for the CM Item including Model, Variant and Position.
    If the user is creating a partial asset assembly, and the CM Item is used in multiple positions, they should select the record in the lookup with the specific position corresponding to the assembly they wish to create.

  4. Enter other required information, for example: Serial, Registration, Asset Status.

  5. Specify a Location. If an Inventory Location is specified then the Asset will be added into the Storeroom on creation.

  6. Specify a Receipt Date and (optionally) a Date of Manufacture.
    Be aware that transactions, for example installation and removal of child assets can not be performed with an "As of Date" that is before the Receipt Date or Date of Manufacure (which ever is the earliest date).

  7. Enter Sub Assembly Prefixes. The Asset Prefix and Suffix values will be concatenated to form the asset number of each sub assembly asset.
    For example the Asset Prefix: "RTMT001-" and Suffix: "001" will result in sub assembly (child) assets being generated with the Asset numbers, RTMT001-001, RTMT001-002, RTM001-003 etc.
    This is useful when creating demo or test asset assemblies. Again the asset numbers for child assets (PLUSANEWSUB.ASSETNUM) can also be configured to use the standard Asset autokey.

  8. Enter Serial Prefix and Suffix values. The same logic is used to generate serial numbers for child assets as for the Asset numbers.

  9. Add the meters required to track life against the asset. The meters will be, by default, automatically added to all of child assets within the assembly.
    Note that the action "Create Meters from CM Build" will analyse all Master PMs linked to the CM Item specified. Any meters used on the Meter Frequency, of these related Master PMs, will then be added to the Meters table of the New Asset Assemblies record.

  10. Click the action "Create Sub Assemblies form CM Build". This will generate sub assembly information, based on the selected CM Item, Model, Variant and Position, from the related Model data and build hierarchy.

  1. On the "Sub Assembly Details" tab review the information for each of the sub assembly records to confirm accurate serial numbers, meter information etc.

  2. Change the status of the NAA record to ACTIVE (once the user has confirmed that all data is accurate).

  3. Click the "Create Asset" action to initiate the creation of the asset hierarchy.

    The user can choose to launch the action in the background and be notified by email on completion. This can be useful for large asset hierarchies where it may take some time to generate the entire asset hierarchy.
    Before the asset creation process is actioned the system will first verify that any Rotating Items linked to the asset or its children are valid within the Organization where the asset is to be created.

The New Asset Assemblies information can be created or updated using the Maximo Integration Framework (MIF). An example is provided in MXLoader file is provided in the Loading Data topic. This can be useful to peform a bulk update of serial numbers, CM Items, meter information or related data before the asset creation action is executed.

Using the Asset Autokey to generate Asset numbers​

In order to configure the system to generate Asset numbers, of new asset assembly records, using the standard Asset autokey a direct database update must be performed:

UPDATE maxattribute SET autokeyname='ASSETNUM', canautonum=1, defaultvalue='&AUTOKEY&' WHERE objectname='PLUSANEWASSET' AND attributename='ASSETNUM';
UPDATE maxattributecfg SET autokeyname='ASSETNUM', canautonum=1, defaultvalue='&AUTOKEY&' WHERE objectname='PLUSANEWASSET' AND attributename='ASSETNUM';
UPDATE maxattribute SET autokeyname='ASSETNUM', canautonum=1, defaultvalue='&AUTOKEY&' WHERE objectname='PLUSANEWSUB' AND attributename='ASSETNUM';
UPDATE maxattributecfg SET autokeyname='ASSETNUM', canautonum=1, defaultvalue='&AUTOKEY&' WHERE objectname='PLUSANEWSUB' AND attributename='ASSETNUM';

Converting existing Assets into CM Managed Assets using New Asset Assemblies​

The New Asset Assemblies application can also be used to "convert" an existing Maximo asset hierarchy, of non-configuration managed assets, into one which is CM managed. It does this by updating the existing non-cm assets with the information necessary for the system to regard them as CM managed assets eg setting the CM Item on the ASSET record.

In order to do carry out this conversion processing:

  1. The "Existing Asset" field should be populated with the existing non-cm managed asset number.
  2. Generate the sub assemblies using the "Create Sub Assemblies from CM Build" action.
  3. Update the asset number field on each sub assembly record to specify the existing non-cm managed asset number that will be placed in the corresponding position.
  4. Use the "Create Asset" action. The user will be presented with a dialog, listing each existing asset record, and ask the user to confirm the update to these existing asset records (to convert them into CM Managed assets).

The conversion process will update the existing ASSET record to set the CM Item, Model, Variant and other CM managed data and attributes.
If the asset does not have an parent it's parent will be updated to that corresponding to its position within the Build Hierarchy of the Model used.
Meters will be added to the existing assets if they do not already exist.
