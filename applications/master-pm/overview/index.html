Master PM (CM)

Overview​

The Master PM (CM) application enables the creation of master maintenance records which are linked to one or more CM Items. The application also provides additional functionality, for configuration-managed assets, over and above that provided by standard Maximo.

Additional functionality provided in the Master PM (CM) application:

CM Items​

The CM Items table provides the ability to associate one or more CM Items with a Master PM.
This enables the system to automatically create PMs from the Master PMs for configuration-managed assets with the CM Item listed on the Master PM.

An action "Create Associated PMs for CM Items" is also provided to facilitate the immediate creation of PMs from the Master PM (for the applicable configuration-managed assets).

PMs which are created automatically are marked as needing review to ensure the next date or meter count at which they will become due is accurate. A dedicated BDI Problem Code: ENR (Event Needs Review) is raised for PMs where this review needs to take place.

Status and Revisions​

Maximo Aviation introduces a Status field to the Master PM record (MASTERPM.PLUSASTATUS). When a new Master PM is created it has an initial status of DRAFT. This enables a user to setup the Master PM and configure it's various fields eg frequency criteria before making the Master PM Active. PMs cannot be created from the Master PM unless it is Active. In addition the system will not automatically create PMs from the Master PM (for applicable Assets) until the Master PM is made Active.

Maximo Aviation also introduces Revisioning functionality to the Master PM (CM) and PM (CM) applications. This operates in a similar way to revision functionality in other Maximo applications for example Job Plans.

Master PM/PM Revision functionality is disabled in ACM by default. It must be enabled within the Organizations (CM) application. This is a system level setting and is contained within the CM Options section of the System Settings dialog. The option is a checbox labelled "Revision Control for Master PM / PM?".

Once enabled, Master PM and PM records become read-only for configuration-managed assets. In order to make changes the record must be revised. This revision action creates a "copy" of the record with a pending revision (PNDREV) status. Once the necessary updates are made to this record it can be made active. The previous revision is placed into history with a status of REVISED. This enables full tracking of what has changed, when and by whom.

The Build Data Interpreter will cause the update of the associated PMs automatically when it next validates the affected assets. Alternatively the action "Update Associated PMs?" will also trigger this immediately.

Extendable PMs​

The Extendable checkbox, when set to true, indicates that the associated PMs as having the ability to be extended. A PM Extension is a controlled process to allow the Due date or Due Count to be extended for the next occurence of the PM. The PM Extension can be created in the PM (CM) application or the PM Extensions (CM) application. A workflow can be created against a PM Extension to create an approval process to activate the extension. PM Extensions are discussed in more detail in a separate topic.

Master PM / PM Actions​

The Master PM Actions provides the ability to define actions for the current "primary" PM which cause an action to be performed against a "secondary" Master PM/PM. These actions are automatically executed when specific events occur with the system such as work order completion or asset removal and install.

The Master/PM actions are limited to primary / secondary PMs for the same CM Item or configuration-managed asset. That is to say, it is not possible to define an action on a primary PM, for a configuration-managed asset, which effects a secondary PM for a different configuration-managed asset.

A list of the available action types, their associated effect and what triggers the action is detailed below:
