Models (CM)

Overview​

A model defines the engineering reference data and the allowable configuration for a type of complex asset.

It's used:

  • To defined the allowable configuration for a type of complex asset and possibly variants of that asset type.
  • As a template from which to build asset hierarchies used to maintain assets of the type described by the Model.
  • By the BDI to validate the as maintained configuration of the asset against its allowable configuration described by the Model (and highlights problems).

Models Main Page​

The Models main page contains general information about the Model and fields which control it's definition.

Build Items, Label and CM Items​

The Build Items are a list of the main components (typically tracked and serialized) that are then used to create a build hierarchy representing the physical structure of the complex asset.
They are related to one or more labels (typically one) and one or more CM Items which represent parts which provide the same fit, form and function of the component.

Each Build Item records name must be unique within the Model it is contained within.

When defining the Build Items and Build Hierarchy of a Model it is recommended that it is defined to the level at which it needs to be tracked and maintained in practice. Over-engineering an ACM model definition can lead to performance issues, user frustration, and increased maintenance overhead.


The goal should be to model only what needs to be controlled or validated, and no more. Always try to balance precision with usability.
